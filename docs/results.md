# Benchmark results

Regenerated by `scripts/run_benchmarks.sh` — edit that, not this file.

Hardware: Intel Core i7-1165G7 (4 physical cores / 8 threads), Linux, GCC 13.3, CMake Release build.
Workload: 4000 CPU-bound tasks, 100000 work-units each. Best of 3 runs per worker count.
Speedup is relative to the same scheduler running with 1 worker.

| workers | tasks/sec | speedup |
|--------:|----------:|--------:|
| 1       | 3979      | 1.00x   |
| 2       | 8345      | 2.10x   |
| 4       | 16478     | 4.14x   |
| 6       | 23072     | 5.80x   |
| 8       | 29233     | 7.35x   |

Near-linear scaling to 4 workers (matching the 4 physical
cores), with continued, smaller gains through 8 hardware threads
(hyper-threading).

One caveat on reading these: the single-worker baseline is stable run to
run, but the figures above 4 workers move by 10-20% between
invocations on thermally-constrained hardware, because sustained
all-core turbo clocks drop as the package heats up. Treat the
hyper-threaded rows as a range, not a fixed number.
