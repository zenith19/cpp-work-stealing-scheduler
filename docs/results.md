# Benchmark results

Regenerated by `scripts/run_benchmarks.sh` — edit that, not this file.

Hardware: Intel Core i7-1165G7 (4 physical cores / 8 threads), Linux, GCC 13.3, CMake Release build.
Workload: 4000 CPU-bound tasks, 100000 work-units each.
Sampling: 10 runs per worker count; the median is reported, with the slowest and
fastest run alongside it. Speedup is median relative to the 1-worker median.

| workers | median tasks/sec | min | max | speedup |
|--------:|-----------------:|----:|----:|--------:|
| 1       | 4040             | 3900 | 4161 | 1.00x |
| 2       | 8306             | 7104 | 8417 | 2.06x |
| 4       | 16986            | 16560 | 17114 | 4.20x |
| 6       | 23488            | 22376 | 23828 | 5.81x |
| 8       | 27423            | 26294 | 30603 | 6.79x |

Throughput tracks the ideal line closely through the 4 physical
cores, then keeps climbing with diminishing returns across all 8
hardware threads (hyper-threading). Where a median sits slightly above
the ideal line, that is the 1-worker baseline drifting, not super-linear
scaling — see the spread below.

The min and max columns are the point of this table. The widest row spans 16% of
its own median, because sustained all-core turbo clocks fall as the package heats
up on thermally-constrained hardware. A best-of-N figure would report only the
luckiest run and hide that entirely, so the median is reported instead.
